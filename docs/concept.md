# WFRP4e Crafting («Гильдия ремёсел») - концепт

Модуль Foundry VTT (V13/V14) для системы WFRP4e (9.x): крафт по рецептам - книга рецептов,
создание предметов по правилам «Создание предмета» (Книга правил, стр. 199), редактор рецептов для ГМа.
Отдельный репозиторий, та же инфраструктура, что у wfrp4e-paperdoll (релизы с GitHub, мок, QA, ru/en).

## Правила игры, на которые опираемся (сверено с книгой)

- «Создание предмета» - затея между приключениями (стр. 199): нужен навык ремесла,
  инструменты, сырьё и мастерская. Сырьё = 1/4 цены результата, покупается заранее.
- Процесс - ПРОДОЛЖИТЕЛЬНАЯ проверка ремесла (стр. 154): УУ копится от проверки к проверке,
  если суммарный УУ падает ниже 0 - проверка провалена.
- Сложность по доступности предмета: распространённый +20, редкий +0, раритетный -10, экзотический -30.
- Требуемый УУ по уровню цены: медный 5, серебряный 10, золотой 15+.
- Достоинства/изъяны: каждый изъян снижает требуемый УУ вдвое, каждое достоинство +5 (после изъянов).
- Одна затея = одна проверка ремесла. Незаконченный проект хранится.
- Навык «Ремесло» (стр. 127): при наличии инструментов и ресурсов обычные задачи ремесла
  проверки НЕ требуют - проверка нужна для сжатых сроков, плохих условий, изобретений и качественных вещей.
- Таланты: «Мастер своего дела (ремесло)» - каждый уровень снижает требуемый УУ на 1;
  «Фармацевт» - перевернуть провал проверки ремесла (аптекарь); «Поспешное бегство» - одна затея
  создания предмета ремеслом (аптекарь) бесплатно и без мастерской; «Мастер на все руки» - починка
  любым ремеслом как общим навыком; «Умелец (ремесло)» - навык в схеме любой карьеры.
- «Изобретение!» (стр. 196): задумка (чертёж - проверка ремесла (инженер), её УУ идёт бонусом
  к воплощению) + воплощение (создание предмета, сложность не ниже безумной -30, сырьё = 2x цены
  скомбинированных предметов, нужны навыки всех составляющих).

## Главный принцип (как в paperdoll)

Свой движок правил не пишем. В системе есть тип предмета `extendedTest`
(src/model/item/extendedTest.js): `SL.current/target`, `test.value` (название навыка),
`difficulty`, `failingDecreases`, `negativePossible`, `completion`. И есть
`actor.setupExtendedTest(item)` (src/documents/actor.js:274) - системный диалог броска,
модификаторы, таланты, фортуна, накопление УУ - всё делает система.
Крафт-проект = системный extendedTest на актёре, созданный модулем. Мы - интерфейс и логистика
(рецепты, ингредиенты, деньги, выдача результата).

## Что строим

### 1. Рецепт - подтип предмета модуля (`wfrp4e-crafting.recipe`, Foundry v11+ module subtypes)

Поля:
- результат: UUID предмета + количество (что появится в инвентаре);
- навык: ремесло (специализация), можно список альтернатив («кузнец ИЛИ оружейник»);
- сложность (дефолт по доступности результата, редактируется);
- требуемый УУ (дефолт по уровню цены, редактируется);
- ингредиенты: список { предмет (UUID/имя) ИЛИ «любой с тегом», количество, расходуется? };
- деньги (сырьё): дефолт 1/4 цены результата, редактируется; можно «только деньги, без ингредиентов»;
- условия: нужна мастерская?, нужные инструменты (предметы-требования, не расходуются);
- провал ниже нуля: что теряется (ничего / половина сырья / всё сырьё) - из настроек, можно переопределить;
- описание/картинка - обычные поля предмета.

Рецепт - это предмет, значит ГМ раздаёт его как угодно: лут, покупка, обучение, компендиум.
Перетащил на актёра = персонаж ВЫУЧИЛ рецепт.

### 2. Книга рецептов (окно игрока, референс - алхимия из Kingdom Come: разворот книги)

- Слева - список известных рецептов (те, что лежат на актёре) с фильтрами:
  все / могу сделать сейчас / не хватает ингредиентов / не хватает навыка. Поиск, группировка по ремеслу.
- Доступные к изготовлению - ПОДСВЕЧЕНЫ (есть навык, ингредиенты, деньги, инструменты).
- Справа - разворот рецепта: карточка результата, ингредиенты (есть - галка, нет - подсвечено красным,
  сколько не хватает), навык и целевое значение персонажа со сложностью («Ремесло (аптекарь) 45 +20»),
  требуемый УУ с учётом талантов («нужно 10 УУ, с „Мастер своего дела" - 8»), стоимость сырья,
  время (наративное поле), кнопка «Создать».
- Вкладка «В работе»: активные проекты с прогресс-баром (SL.pct из системы), кнопка «Продолжить»
  (ещё одна проверка), «Бросить» (с подтверждением - сырьё уже потрачено).
- Рецепт может быть известен, но недоступен - он виден всегда, просто не подсвечен,
  и видно ЧЕГО не хватает.

### 3. Процесс

1. «Создать»: модуль списывает ингредиенты и деньги, создаёт на актёре extendedTest
   (test = «Ремесло (аптекарь)», difficulty, SL.target с учётом достоинств/изъянов и талантов).
2. Бросок: `actor.setupExtendedTest(...)` - системное окно, кубы кидает система, результат в чат.
3. УУ достиг цели - модуль создаёт предмет-результат в инвентаре, карточка в чат
   («Создано: Лечебная настойка x2»), проект закрывается.
4. УУ ниже нуля - провал: карточка в чат, сырьё теряется по настройке.
5. Всё на правах игрока (свой актёр) - сокеты и ГМ-посредник для ядра не нужны.
   Опция «крафт только с одобрения ГМа» - позже, если понадобится.

### 4. Редактор рецептов ГМа

- Лист рецепта (обычный item sheet подтипа).
- Мастер «рецепт из предмета»: ГМ перетаскивает любой предмет - модуль сам подставляет
  навык по типу/названию, сложность по доступности, УУ по цене, сырьё 1/4 цены. Остаётся поправить
  ингредиенты и сохранить.
- Стартовый компендиум рецептов: зелья/настои аптекаря, еда повара, стрелы, простые инструменты -
  чтобы модуль работал из коробки.

### 5. Режимы темпа (настройка мира)

- «По правилам» - одна проверка за затею, кнопка «Продолжить» активируется ГМом
  (кнопка «Новая затея» / конец приключения);
- «Свободный» - бросать можно когда угодно (для столов, где затеи не отыгрываются).

## Фазы

- v0.1 (ядро): подтип рецепта, книга с подсветкой и фильтрами, создание extendedTest,
