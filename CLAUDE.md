# Книга рецептов WFRP (wfrp4e-recipe-book) - контекст для Claude Code

Модуль Foundry VTT (V13/V14) для системы WFRP4e (9.x): крафт по рецептам - книга известных рецептов
с подсветкой доступных, создание предметов по правилам «Создание предмета» (Книга правил, стр. 199).
Автор - Михаил (rain2rock). Пока бесплатный, потом станет платным. Отдельный проект, но одна семья
с wfrp4e-paperdoll: дизайн-токены и палитры взяты оттуда (rb-* вместо pd-*), подход тот же.
Концепт и правила игры: docs/concept.md.

## Как общаться

- Русский язык, дружелюбно, «бро», мужской род. Кратко. Перед работой уточнять недостающее.
- Только дефис «-», никогда длинное тире «—». Кавычки русские «...».
- Сначала показать результат (скриншот мока), если просят «покажи».

## Гит - строгие правила

- Ничего не коммитить и не пушить, пока Михаил не скажет «заливай» (или «отправляй в гит»).
- По «заливай» - ВСЁ одним коммитом, сообщение короткое (`v0.1.0: <что>`).
- Перед пушем поднять версию в `module.json` (пуш в main с новой версией запускает релиз
  через `.github/workflows/release.yml`).
- Не коммитить чужую платную графику; свою (assets/) - можно. Мок (docs/book-mock.html) не коммитим.

## Главный принцип

Свой движок правил НЕ пишем. Крафт-проект - это системный предмет `extendedTest` на актёре
(SL.current/target, test.value - название навыка, difficulty), бросок - `actor.setupExtendedTest(test)`:
диалог, модификаторы, таланты и накопление УУ делает система WFRP4e. Модуль: рецепты, книга,
списание ингредиентов и денег, выдача результата, возврат сырья при провале.

## Структура

- `scripts/recipe-model.js` - подтип предмета `wfrp4e-recipe-book.recipe` (объявлен в module.json
  `documentTypes`), таблицы сложностей (fallback для мока, живые - из `game.wfrp4e.config`).
- `scripts/recipe-book.js` - ядро: деньги (как в paperdoll: COIN_VALUE/moneyPennies/coinUpdates),
  `recipeStatus(actor, recipe)` - статус (навык/ингредиенты/деньги/талант), `startCraft` (списать
  сырьё, создать extendedTest, бросить), `watchCrafting()` - хук updateItem: цель достигнута -
  выдать предмет, УУ < 0 - провал с возвратом сырья по настройке; `RecipeBookApp` (ApplicationV2 +
  Handlebars) - книга: поиск, фильтры (все/могу сделать/не хватает), группы по ремёслам, секция
  «В работе» с прогрессом, разворот рецепта, кнопка «Создать». Рендеры сериализованы очередью
  (`render()` переопределён) - хук updateItem и клики иначе гоняются и старый рендер побеждает.
  Подсказки: ВСЕ через свой `RBTooltip` (порт PaperdollTooltip из paperdoll) - системный
  data-tooltip НЕ используем, он накладывается на наш. Короткие - атрибут `data-rb-tip`
  (разметка tipHtml: 1-я строка заголовок, TAB = значение справа, «! » warn, «~ » сноска,
  «· » пункт), показ с задержкой 250 мс, следует за курсором, не накрывает хотбар.
  Богатый ховер ингредиентов и результата - `[data-rbtt]` + скрытый `.rb-tt-src` в строке
  (`_itemTip`: картинка, цена, доступность, «в наличии/нужно», описание; источник - предмет
  актёра, иначе fromUuid).
  Иконки монет ЕДИНЫЕ для всего модуля - `coinImgs()`: пути wfrp4e-core (если модуль активен),
  иначе картинки с монет-предметов любого актёра, иначе CSS-кружки. Кэшируются на сессию.
  Время рецепта - timeDays/timeHours/timeMinutes, показ `fmtTime`: «1д 3ч 15м», только ненулевое.
  Инструменты - массив tools[{uuid,name,img}]: предметы из базы, НЕ расходуются, проверяются
  у персонажа по имени (нет - рецепт недоступен, строка красная «нет»).
- `scripts/recipe-sheet.js` - лист рецепта для ГМа: дроп предмета-результата автозаполняет
  сложность по доступности, УУ по цене (медь 5 / серебро 10 / золото 15), сырьё = 1/4 цены; 
  (`suggestFromItem`); дроп ингредиентов и инструментов, три поля денег (зк/сш/мп) складываются
  в пенни (иконки `coinIco` ВНУТРИ полей, слева - обёртка `.rb-coinfield`). Ингредиенты
  и инструменты добавляются также через «+» у заголовка секции - пикер с поиском по базе
  (`itemIndex()`: физические предметы мира и всех компендиумов Item, кэш на сессию);
  клик по картинке рецепта - тот же пикер, иконка берётся с выбранного предмета базы.
  Навык и альтернативный навык - ДРОПДАУНЫ из базы:
  `skillNames()` собирает предметы-навыки из мира и всех компендиумов Item (кэш на сессию),
  ремёсла первыми; текущее значение всегда добавляется в список.
- `scripts/main.js` - init: модель, лист, настройки, клавиша B, кнопка в шапке листа актёра,
  хелперы eq/gt, `api.open(actor)`.
- `styles/rb-system.css` - токены (копия палитр paperdoll: пергамент - дефолт, тёмная -
  `.rb-theme-dark`), кнопка `.rb-btn`, кружки монет `.rb-coin-dot`, чипы `.rb-filter`.
- `styles/recipe-book.css` - разворот книги и лист рецепта. Цвета и размеры - только токенами.
- `templates/book.hbs`, `templates/recipe-sheet.hbs`, `lang/ru.json`, `lang/en.json`.
- `assets/icons/` - свои иконки Михаила, скопированы из wfrp4e-paperdoll/assets/icons (коммитить можно);
  `recipe-default.png` - дефолтная картинка нового рецепта (ставится хуком preCreateItem),
  `assets/ui/ui-sheet-button.png` - кнопка-книга в шапке листа актёра. Остальные - для мока
  и будущего компендиума. Шрифты НЕ навязываем - наследуем от Foundry, как paperdoll
  (в моке - стек Signika и FontAwesome с CDN, тоже как в моке paperdoll).
- `tools/starter-recipes.json` - 14 стартовых рецептов (черновик DeepSeek) - для будущего
  компендиума (v0.2), пока никуда не подключены.

## ГМ-цикл рецептов

- «+ Новый рецепт» (книга, низ левой страницы) - создаёт рецепт В МИРЕ
  (вкладка «Предметы») и открывает лист; книга переключается на вкладку «Мир».
- Вкладка «Реестр» (чип-фильтр, только ГМ): ПОЛНЫЙ список - рецепты мира (группа «Мир»,
  всегда первая) + копии у всех персонажей, группировка по владельцу (версии одного рецепта
  у разных персонажей различаются - это норма). Статус/ховеры чужого рецепта считаются
  против ЕГО владельца. Действия: «Выдать персонажу» (список персонажей игроков; владельцу
  открытой книги - с переходом к рецепту), «Изменить» (лист), «Удалить» (мировой - насовсем,
  у персонажа - из его книги). Выбор из реестра сбрасывается при уходе на личные вкладки.
- У рецепта персонажа ГМ видит корзинку «удалить из книги» (забыть, мир не трогает).
- Настройка «Фильтры по ремеслу и типу» (клиент, по умолчанию ВЫКЛ): две выпадашки под
  чипами - по ремеслу и по типу создаваемого предмета (тип - fromUuidSync по result.uuid,
  кастомный результат = trapping; подписи типов - TYPES.Item.* системы).
- Настройка «ГМ: вид игрока» (клиент, СЕРВИСНАЯ - для тестов): скрывает весь ГМ-интерфейс
  (вкладку «Мир», создание/изменение/удаление) - ГМ видит книгу как игрок. Живёт в настройках
  модуля Foundry (в книге кнопки нет), в моке - кнопка «Вид: ГМ / игрок» в верхней панели.
  Проверка в коде - `isGMView()`.
- Лист рецепта: снапшот при открытии; футер «Отмена» (откат к снапшоту) / «Сохранить как
  новый» (правки уходят в НОВЫЙ рецепт мира, исходный откатывается) / «Сохранить» (закрыть).
  Закрытие крестиком = сохранить (живое редактирование, как обычно в Foundry).
  Рецепт, созданный С НУЛЯ (флаг fresh, ставит #onCreateRecipe): «Сохранить как новый»
  скрыт, «Отмена» УДАЛЯЕТ недосозданный рецепт; «Сохранить» или крестик снимают флаг -
  дальше лист работает в режиме редактирования.
- Результат рецепта: предмет из базы (дроп или «+») ИЛИ полностью новый - имя вписывается
  руками (при совпадении имени с предметом базы - перепривязка); новый предмет создаётся
  при завершении крафта с описанием рецепта. Иконка РЕЦЕПТА (клик по картинке в листе,
  пикер из базы) и иконка РЕЗУЛЬТАТА (с предмета-результата) - РАЗНЫЕ, не синхронизируются;
  в списке книги показывается иконка РЕЗУЛЬТАТА (иконка рецепта - запасная).

## Дизайн-система

Токены и базовые компоненты - `styles/rb-system.css` (подключается первым), витрина со всеми
образцами - `docs/styleguide.html` (`npm run styleguide`, переключатель тем на странице).
Палитры и подход - семейные с paperdoll (pd-* -> rb-*). Правила, чтобы вёрстка не разъезжалась:

- отступы/зазоры/радиусы - только `--rb-space-*` / `--rb-radius*` (пилюля - `--rb-radius-pill`);
  шрифты - шкала `--rb-fs-*`; цвета - только переменными темы (пергамент дефолт, тёмная -
  `.rb-theme-dark`); размеры - `--rb-icon-s/l`, `--rb-coin`, `--rb-btn-h`, `--rb-btn-minw`, `--rb-num-w`;
- любая кнопка - `.rb-btn` (+ `--craft` акцент, `--quiet`), иконко-кнопки - `.rb-add`/`.rb-remove`;
  чипы - `.rb-filter`, строки - `.rb-row`/`.rb-ing`, заголовки секций - `.rb-block-title`;
  поля стилизуются базовым элементным селектором, числовые - `.rb-num`, монета в поле - `.rb-coinfield`;
- сырые px ловит `tools/qa/dslint.mjs` (входит в `npm run qa`): базлайн НУЛЕВОЙ
  (`tools/qa/dslint-baseline.json`) - не наращивать; новые компоненты добавлять
  в rb-system.css и на витрину, а не в css окна.

## Правила игры, которые зашиты

- Создание предмета (стр. 199): продолжительная проверка ремесла; сырьё = 1/4 цены результата;
  сложность по доступности (распространённый average +20, редкий challenging +0, раритетный
  difficult −10, экзотический veryHard −30); требуемый УУ по цене (медь 5, серебро 10, золото 15+).
- Продолжительная проверка (стр. 154): УУ копится, суммарный УУ ниже 0 - провал
  (ставим `negativePossible: true`, `failingDecreases: true`).
- Талант «Мастер своего дела (ремесло)»: −1 требуемый УУ за уровень; специализация в скобках
  имени таланта сверяется с навыком рецепта, без скобок - действует на всё (минимум цели - 1).
- Рецепт известен = предмет-рецепт лежит на актёре. Ингредиенты ищутся по ИМЕНИ (норм. регистр),
  uuid в рецепте - только для картинки и подстановки.

## Критический успех (v0.1.8)

- Поля рецепта: critEnabled, critSL (порог), ЧЕКБОКСЫ critExtra(+critCount)/critUpgrade
  (+critResult{uuid,name,img})/critRefund + critRandom. Срабатывание: НАКОПЛЕННЫЙ УУ в момент
  завершения >= critSL (finishCraft; конфиг снапшотится в флаги extendedTest при startCraft).
- Эффекты СКЛАДЫВАЮТСЯ (И): extra +N к количеству; upgrade - вместо базового результата
  critResult (количество с учётом extra); refund - возврат половины ингредиентов и денег.
  critRandom (чекбокс виден при 2+ эффектах) - срабатывает ОДИН случайный. Строку «Крит: ...»
  в книге видит ТОЛЬКО ГМ - для игрока крит целиком сюрприз (узнаёт из чат-карточки).
- В книге - строка «Крит: УУ >= N - эффект» в блоке «Проверка»; в чат-карточке - строка
  «Критический успех (УУ X)!» и значок двойной галки.

## Локализация

- Настройка «Язык модуля» (клиент): auto (как Foundry) / ru / en. Реализация - СВОЯ таблица
  переводов поверх i18n: `loadLangs()` грузит оба lang/*.json, `L()/F()` смотрят настройку
  и берут ключи WFRPRB.* из таблицы, иначе падают в `game.i18n`. В шаблонах НЕ `{{localize}}`,
  а хелпер `{{rbL}}` (регистрируется в init) - иначе настройка не действует на шаблоны.
- `module.json` title/description - на английском («WFRP Recipe Book»): название модуля
  в списке Foundry не локализуется.
- Кнопка на листе персонажа: хук `renderActorSheetV2` + запасной `renderActorSheet` (V1-листы).

## Мок и проверки

Мок - настоящий код модуля поверх заглушки Foundry (tools/mock-runtime.js), один html.
`setupExtendedTest` в моке ЭМУЛИРУЕТСЯ (d100 против навык+сложность, УУ = десятки цели − десятки
броска); `window.__RB_FORCE_ROLL__` задаёт бросок для тестов.
```bash
npm install                 # handlebars + playwright
npm run mock                # docs/book-mock.html
npm run qa                  # tools/qa/bookchk.mjs - 27 проверок, все должны быть PASS
```
Склейка мока: import/export срезаются, файлы конкатенируются - НЕ объявлять одинаковые
const на верхнем уровне разных файлов (у recipe-sheet.js из-за этого RBSheetMixin, а не
HandlebarsApplicationMixin).

## Проверено на живом сервере (Foundry + wfrp4e 9.6.3 + dae + libWrapper)

- Миграция системы (`Migration.migrateItemData`) бежит по ЛЮБОМУ предмету в `_preCreate`
  и безусловно читает `system.description.value` и `system.gmdescription.value` - поэтому
  у рецепта оба поля ОБЯЗАНЫ быть формы `{ value }` (исправлено в v0.1.3; до этого создание
  рецепта падало с TypeError, т.е. легаси-рецептов со старой схемой на серверах нет).
- Контракт warhammer-lib: `allApplicableEffects` зовёт `this.system.getOtherEffects()` и прочие
  методы базовой модели - подтип ОБЯЗАН наследоваться от `warhammer.models.BaseWarhammerItemModel`
  (глобал либы; класс собирается на init в `buildRecipeModel()`, порядок загрузки скриптов
  модулей не гарантирован). Голый TypeDataModel не работает - на этом же ломается
  beavers-crafting на wfrp4e (подтверждено Михаилом). Ориентир для подтипов - Forien's Armoury.

## Не проверено в живом Foundry (проверить при первой возможности)

- Регистрация подтипа: создание предмета доходит до системной миграции (значит сам подтип виден); лист и дроп - ещё не проверены.
- Форма сигнатуры `actor.setupExtendedTest` (в системе: context.extended = uuid, бросок может
  идти через диалог - наш rollCraft пытается вызвать t.roll(), если система не бросила сама).
- Обновляет ли система SL.current сама после броска (должна - для системных extendedTest)
  и срабатывает ли наш watchCrafting на этом updateItem (userId).
- Дроп на лист рецепта (формат dataTransfer в V13), submitOnChange формы листа.
- Видны ли предметы-рецепты во вкладке инвентаря системы (не должны ломать лист актёра).
- `renderActorSheetV2` на листах системы 9.x (в paperdoll работает - должен и тут).
